`china-support.md` の座標変換（`backend/src/domain/china.rs`）まわりで出た疑問を整理したもの。
設計判断の背景理解に使う。

関連コード:

- `gcj02_to_bd09ll` — `backend/src/domain/china.rs:102-107`

- `wgs84_to_bd09mc`（コンビネータ）— `backend/src/domain/china.rs:213-217`

## Q1. WGS84 → BD-09 MC の変換はどうやっている？

3 段階の順変換を合成している（逆変換は不要）。

1. **WGS84 → GCJ-02**（中国国家標準、通称「火星座標」）
2. **GCJ-02 → BD-09ll**（百度独自 lng/lat）
3. **BD-09ll → BD-09 MC**（百度独自メルカトル投影、単位メートル）

外部 crate は使わず `china.rs` に自前実装。

---

## Q2. なぜ GCJ-02 は「火星座標（Mars Coordinates）」と呼ばれる？

- **G**uojia **C**ehui **J**u（国家測絵局）が 2002 年に策定した座標系。
- WGS84 に**意図的な非線形オフセット**（暗号化的擾乱）を加えたもの。
- 実測 GPS（WGS84）を中国地図に重ねると 100〜700 m ズレて「火星の上にいるみたい」と揶揄されたのが語源。

---

## Q3. 100〜700 m もズレているのに、百度地図上では 10〜30 m しかズレていないように見えるのはなぜ？

**我々は WGS84 を BD-09 MC に変換してから問い合わせているので、百度の内部座標系と一致している**から。

「ズレ」が可視化されるのは、WGS84 を**そのまま**百度/高德の地図に重ねた時だけ。百度の世界は完全に BD-09 で閉じている:

- 地図タイル（道路網、背景）→ BD-09
- 衛星画像 → BD-09 にワープ済み
- POI、街景パノラマ位置 → BD-09
- ルート検索・距離計算 → BD-09 上で実行

全部が**同じだけ歪んでいる**ので百度の中では内部整合が取れている。

残る 10〜30 m 誤差の出どころ:

| 誤差源 | 寄与 |
|---|---|
| WGS84 → GCJ-02 の近似アルゴリズム残差 | 大（メイン） |
| GCJ-02 → BD-09ll | ほぼ 0 |
| BD-09ll → BD-09 MC | ほぼ 0 |
| OSM ノード自体の精度 | 中 |
| 百度の街景撮影位置の測量精度 | 小〜中 |

## Q4. `wgs84_to_gcj02` は「補正」？

**違う**。「真 → 偽」の写像であり「同じだけ歪ませる」処理。

- WGS84 が**真の座標**（GPS 実測値）
- GCJ-02 が**意図的にズラされた偽座標**
- 中国地図は全て GCJ-02 / BD-09 で描画されている
- なので WGS84 のまま重ねると 100〜700 m ズレる
- `wgs84_to_gcj02` は国家が加えた擾乱を**同じだけ自分の点にも加えて**、中国地図の世界に着地させる

逆変換（偽 → 真）は解析解が無く、反復法で近似するしかない（我々は順方向しか使わないので未実装）。

---

## Q5. `wgs84_to_gcj02` は公式公開アルゴリズム？

**違う。非公開アルゴリズムのリバースエンジニアリング近似**。

- 国家測絵局は式を一切公開していない（国家機密扱い）
- 2000 年代後半、OSS コミュニティが実測ペアを大量に集めて擾乱式を推定
- `eviltransform`, `coordtransform`, proj4 拡張など全ての中国系 OSS で**式が共通**
- `china.rs:71-85` のコードもこのデファクトスタンダードに従っている

精度:
- 東部大都市（北京/上海/広州/深圳）では残差 数 m〜10 m
- 中原・華中では 5〜15 m
- 辺境（新疆・西蔵）では 20〜50 m、最悪 100 m 近く
- 国外（`is_in_china_mainland` が false の領域）では擾乱未定義

## Q6. 3 段階のうち他の変換も推定？公開度の比較

| 変換 | 公開度 | 残差 |
|---|---|---|
| `wgs84_to_gcj02` | **完全に非公開**（国家機密） | 数 m〜数十 m |
| `gcj02_to_bd09ll` | **半公開**（変換 API はあるが式は非公開） | ほぼ 0 |
| `bd09ll_to_bd09mc` | **事実上公開**（係数テーブルが百度 JS SDK に含まれる） | ほぼ 0 |

`gcj02_to_bd09ll` の式（極座標シフト + 正弦擾乱 + 固定オフセット）は構造が単純で、リバースで厳密解に到達できている。全 OSS 実装で `0.00002`, `0.000003`, `0.0065`, `0.006` などの定数が一字一句一致。

## Q7. 100〜700 m ズラしているのは敵国のミサイル避け？

**通俗的にはそう言われるが、実効性は薄い**。より現実的な目的は「規制・情報主権」。

ミサイル避け説が実効薄い理由:
- 現代の巡航ミサイル・ICBM は GPS + 慣性航法 + 地形照合で民生地図を参照しない
- 軍事衛星画像は cm 級で数百 m オフセットは無意味
- 米軍・ロシア軍は独立手段で中国全土を WGS84 測位済み

より現実的な目的:
1. **測量業の規制** — 中国で地図を公開するには国家認可が必要。GCJ-02 強制で外国企業に参入障壁
2. **民生レベルでの位置情報統制** — 勝手な高精度地図公開の抑止
3. **形式的な国防名目** — 立法時の建前
4. **歴史的経緯** — 冷戦期の測量機密文化を 2002 年《測絵法》で明文化

結論: 「ミサイル避け」は象徴的・建前的な説明で、実態は**地図産業の許認可制と情報主権の道具**。

## Q8. 米軍・ロシア軍はどうやって中国全土を WGS84 で測位しているのか？

衛星画像だけでなく複数の独立手段の組み合わせ。

1. **測地衛星による直接測位**
   - GPS/GLONASS/Galileo 受信機を地上に持ち込めば即 WGS84
   - SLR（衛星レーザー測距）/ VLBI で固定点を直接測位
2. **偵察衛星の画像解析**
   - KH シリーズ（Corona → KH-11）、現行 NRO の光学・SAR 衛星
   - 衛星軌道を WGS84 で精密追跡しているので画像に直接座標を紐付け可能
3. **地形・重力場の全球測量**
   - SRTM（2000 年、WGS84 基準、一般公開）
   - GRACE / GOCE（重力場、楕円体モデル精緻化）
4. **冷戦期の地上観測**
   - 1950〜80 年代から周縁・国境で地上測量・電波源方位測定
5. **中国公開データの逆利用**
   - 軍民両用衛星画像（高分系列）、IGS に流れる GNSS 観測網データ

物理実体の真座標は相手国から見れば独立手段で完全に測れる。GCJ-02 擾乱は「民生公開地図データ」だけにかかるレイヤー。

## Q9. なぜ百度は GCJ-02 からさらに BD-09 へ変換している？

公式表明はないが複数の合理性（重要度順）:

1. **競合との囲い込み（ロックイン）— 最有力**
   - 高德・騰訊は GCJ-02 のまま、百度だけ追加変換
   - 百度 API で開発すると他社地図への乗り換えに全座標の再変換が必要
2. **データ流出・スクレイピング対策**
   - POI データがクロールされても BD-09 のまま、他地図に重ねられない
   - 抽出元が一目瞭然で法的追及も容易
3. **技術的正当性（Mercator 投影）**
   - BD-09 MC はタイル配信・ズーム計算・近傍検索に最適化された独自直交座標
4. **歴史的経緯**
   - 後発サービスとしての差別化戦略
5. **法規制上の安全マージン**
   - GCJ-02 のリバース精度が上がっても BD-09 層で保護

つまり **GCJ-02 が国家の都合、BD-09 が企業の都合**という二層構造。

## Q10. `wgs84_to_gcj02` の誤差は都心と地方で違う？

「オフセット自体の大きさ」と「近似式の残差」は別物なので分けて考える。

### オフセットそのもの（WGS84 と GCJ-02 の乖離）

| 地域 | オフセット |
|---|---|
| 北京・天津 | 約 400〜500 m |
| 上海 | 約 500〜600 m |
| 広州・深圳 | 約 400〜500 m |
| 成都・重慶 | 約 500〜600 m |
| 新疆・西蔵 | 約 500〜700 m |
| 海南・南部沿岸 | 約 300〜450 m |
| 国境・海上 | 不連続・未定義に近い |

都心と地方の差より、**経緯度による変動**の方が大きい。

### 近似式の残差（真の GCJ-02 との差、実用上こちらが重要）

| 地域 | 残差 |
|---|---|
| 東部沿岸大都市（北京/上海/広州/深圳） | 数 m〜10 m |
| 中原・華中（武漢/鄭州/西安/成都） | 5〜15 m |
| 東北（瀋陽/大連/ハルビン） | 5〜15 m |
| 内陸辺境（雲南/貴州/甘粛） | 10〜25 m |
| **新疆・西蔵** | **20〜50 m（最悪 100 m 近く）** |
| 国境線近傍 | 不安定 |

**東部 vs 西部の差が支配的**。推定式は東部の実測ペアに偏ってフィットされているため。

### プロジェクトへの影響

上海パイロット（121.47E, 31.23N）:
- オフセット: 約 500 m
- 近似残差: 約 5〜10 m
- **10 m 閾値で panoid マッチはほぼ問題なし**

将来展開時:
- 北京・深圳・成都・武漢等の主要都市は上海同等の精度
- 新疆・西蔵は 10 m 閾値を超える可能性あり（正しい panoid なのに距離超過で捨てる）
- 辺境地域対応時は閾値緩和や最新近似式への差し替えが論点
